# 1. Record architecture decisions

Date: 2026-11-02

## Status

Accepted

## Context

We need to record the architectural decisions made on this project. This lets current and future team members understand why the system is the way it is and revisit decisions when circumstances change.

## Decision

We will use Architecture Decision Records (ADR), as [described by Michael Nygard](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions), the same format other Access to Justiz (A2J) repositories use.

New decision records live in `doc/adr` and are created by copying the [template](./template.md) or with [`adr-tools`](https://github.com/npryce/adr-tools). The [README](./README.md) contains an autogenerated table of contents of all ADRs.

We will record important decisions already made in follow-up ADRs.

## Consequences

The reasons behind decisions are documented next to the code and reviewed in pull requests. When a decision changes, a new ADR supersedes the old one instead of editing it.
